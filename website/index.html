What the NPU does

A long prompt gives the NPU enough work to help. It handles eligible matrix multiplies and nearby operations. Attention and the reply stay on your GPU.

What we've tested so far

Windows 11, Ryzen AI 9 HX PRO 370, Radeon 890M, and Lemonade 2026.43.3. The actual desktop app and local API both ran NPU-assisted prompts.

This preview uses the bundled b10944 backend. Speed depends on your model, and converted weights use extra RAM. Linux NPU hardware and Strix Halo haven't been verified by this project.

Which GGUF models can I use?

This works across many GGUF models through the llama.cpp backend. The Qwen, LFM, and Granite models in our tests are examples, rather than a fixed model list. You don't need an ONNX or Q4NX export, or a separately compiled NPU kernel for each model. Your GGUF must work with the bundled b10944 build; the add-on's operation coverage, available memory, and hardware also matter. Some models get little benefit or run faster on the GPU alone. See the model results and limitations.

What if my NPU is unavailable?

The launcher checks it before starting and chooses the GPU if the check fails. It records the reason in device-probe.log. If the NPU fails during a request, this preview retries the failed work on the GPU and uses the GPU from then on. The CPU reference is still available if the GPU can't run that piece. The test report keeps the original preview's slow CPU recovery result for comparison.

Why isn't the NPU busy on every message?

Prompt chunks below 1,024 tokens normally stay on the GPU. Try a longer passage. The first long request also includes the cost of preparing the NPU's weight copies. Lemonade's GPU recipe label doesn't tell you whether the add-on ran; check the NPU call counts in the server log.

How do I return to my usual Lemonade setup?

Stop this server with Ctrl+C, restart your normal Lemonade tray server, and restore the app's previous Base URL, normally http://localhost:13305. The launcher uses a separate configuration directory.

Can I use llama.cpp directly?

Yes. The backend and npu launcher still support direct llama.cpp use on Windows and Linux. The technical guide has those commands, build instructions, standalone benchmarks, and the memory and accuracy limits.
